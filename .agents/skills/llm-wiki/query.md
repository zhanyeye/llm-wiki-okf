# query

**以 `wiki/` 为主，raw/ 为回退补充。** 不要通读 `AGENTS.md`；不要一次 Glob/Read 整库；不要读 `ingest.md` / `references/`（唯一例外：§Archive 存档时按需读 [references/okf.md](references/okf.md)）；不要把仓根 `index.md` / `README.md` / `script/` / `tools/` 当正文。

## 搜索范围策略

1. **优先搜 `wiki/`**：OKF 格式的编译结果（frontmatter、type、tags 等结构化信息）
2. **回退搜 `raw/`**：当 wiki/ 无命中或命中结果不充分时，在 raw/ 中继续全文搜索
3. **两者都找不到**：才返回"未在 wiki 中检索到"

> 原始设计参考：[Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

## 流程

### 1. 理解问题

从用户原话提取检索词，保留原始报错和专名，不要求用户使用 `system:` / `tags:` 等特殊语法：

- 系统、组件、环境、资源名
- 症状、动作、期望结果
- 报错原文、错误码、日志片段
- 中文/英文写法、缩写、明显别名和词形变体

扩展词只用于召回页面，不能作为内网事实写进答案。问题缺少系统或环境信息时先检索；仅当不同解释会导致步骤明显不同时，再追问一个关键问题。

### 2. 导航与召回

1. 读 `wiki/index.md`（不是仓库根 `index.md`），了解当前分组。
2. 根据意图优先看可能的分组及其 `index.md`：
   - **现象不明 / 排障** → `wiki/故障排查/index.md`（若存在）
   - **已知系统 / 原理 / 链路** → 系统与架构
   - **怎么操作 / 变更 / 回滚** → 操作手册
   - **入口 / 负责人 / 日志路径** → 资源注册表
   - **短报错 / 常见问法** → 常见问题
3. 分组导航不是硬前置。无对应 index、index 无命中、用户问题跨分组或措辞模糊时，直接在 `wiki/` 做全文召回，搜索：
   - 文件名、index 条目和 frontmatter：`title`、`description`、`tags`、`domain`
   - **正文全文**：用户原词、完整报错片段、拆分后的实体/症状词及其明显变体
4. 搜索不区分大小写；优先完整短语，再搜词组组合，最后才搜单个宽泛词。不要一次 Glob/Read 整库；搜索命中路径后再按需打开。
5. **回退机制**：`wiki/` 全文搜索无命中或命中结果不充分时，立即在 `raw/` 中继续全文搜索（不限于某一子目录）

### 3. 核验候选

1. 按以下顺序选择候选：标题/标签精确命中 > 报错或症状正文命中 > 多个关键词共同命中 > 单个宽泛词命中。
2. 通常打开最相关的 2–5 篇正文；没有相关页不要凑数。跨页回答时确认页面确实互补，不能只因同分组就拼接。
3. 首轮不足时，可用已打开页面中出现的组件名、上下游名或术语再做一轮定向搜索；仍无新增命中就停止，避免无界搜索。
4. 区分”命中页面”和”页面足以回答”：
   - wiki/ 有命中但正文没有具体步骤或完整信息 → **立即回退 raw/ 搜索**（不停止）
   - wiki/ 和 raw/ 都有内容时，wiki/ 不足的部分用 raw/ 补充，标注「⚠️ raw 内容，尚未编译」
   - 只有 wiki/ 和 raw/ 都无相关信息时，才说”未在知识库中检索到”
5. 检查 frontmatter：
   - 已过 `stale_after` → 标明「可能过期」
   - 没有 `verified` → 标明「未经人工确认」
   - `status: deprecated` → 不作为默认操作依据；如必须引用，明确标明已废弃

### 4. 覆盖度诊断

- `wiki/` 中除 `index.md`、`log.md` 外没有概念页 → **立即回退到 `raw/` 全文搜索**（可能包含未编译的原始文档）
- `wiki/` 无命中但 `raw/` 有相关内容 → 标注「⚠️ 原始内容，尚未编译为 OKF 格式」，酌情直接引用或建议入库
- `wiki/` 和 `raw/` 都无命中 → 说”未在知识库中检索到”，简要说明用过的关键实体/症状词，便于用户判断是换词还是补库

## 自动化执行

用户要求执行操作时（「帮我跑磁盘水位脚本」「安装毕昇编译器」等），按以下流程：

1. 在 `wiki/` 找到对应 Runbook / Playbook 页面（走上面查询流程）。
2. 检查 frontmatter `automation.ready`：
   - **`true`** → 读 `automation.script_ref`，用 Bash 执行 `script/<name>/<file>`，传参来自 `automation.params`
   - **`partial`** → 按正文步骤手动执行（命令逐条给用户确认或由 Agent 按参数组装命令）
   - **无 automation 块 / `false`** → 按正文步骤指导用户操作
3. 执行前确认前置条件（Runbook「前置检查」小节）。
4. 执行后运行验证步骤（Runbook「验证」/ Playbook 对应确认步骤）。
5. 结果写入 `wiki/log.md`。

**安全边界**：Agent 不自动执行涉及以下内容的脚本，需人工确认：
- 删除数据（`rm -rf`、`TRUNCATE`）
- 修改认证/密钥配置
- 生产环境变更
- 没有回滚步骤的操作

## 输出标准

- 引用所用页面路径（对话中用仓根相对路径，如 `wiki/操作手册/页.md`）。
- 命令、主机名、集群名、地址**只来自已打开的页**；页内占位符保持原样，不要替换成臆造值。
- 故障排查 index 中该项为「待入库」、或没有正文 → 回答「没有成文步骤」；可指出最接近的已有页，不要补全内网命令或主机名。
- wiki 里没有的事实 → 说「wiki 里没有」，建议按 [ingest.md](ingest.md) 补；不要编。
- 有价值的排查树 / 对比表：问是否回写成新页（[ingest.md](ingest.md)）。
- 答案详略与问题风险相称。简单入口/FAQ 可直接回答；排障、变更和操作问题默认组织为：
  1. **结论与适用范围**：当前最可能的判断，以及页面覆盖的系统/环境。
  2. **处理步骤**：按依赖顺序给出可执行步骤；正文没有的步骤明确标缺失。
  3. **验证与升级**：如何确认恢复、何时停止或升级；页面没写则直说。
  4. **依据与风险**：列出页面路径，并集中标注过期、未验证、已废弃等状态。
- 不要为了简洁省略正文已有的前置检查、验证、回滚或升级条件；也不要为套模板重复信息。

## Archive（可选）

用户明确要求把对话答案存档进 wiki 时：

1. 按 [references/okf.md](references/okf.md) 选 type/目录写新页；`sources` 链到被引用的 wiki 页（bundle 路径），不写 raw。
2. 始终新建页，不合并进已有概念页。
3. 更新分组 index 与 `wiki/log.md`（见 [references/index-log.md](references/index-log.md)）。

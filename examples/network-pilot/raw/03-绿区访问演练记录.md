# 完全虚构来源：demo 绿区外联演练记录

> 本演练、命令、实例和负责人完全虚构；不得复制到生产环境。

目标：让 `demo` 绿区服务通过 `demo-egress-proxy-01` 访问 `https://vendor-api.example.invalid/health`。演练前确认服务属于虚构绿区、DemoDNS 可解析目标，并已安装 DemoCA 的 demo 信任包。代理配置入口为 `https://proxy-console.example.invalid`，负责人 `demo-network-team`；观测入口为 `https://proxy-dashboard.example.invalid`。生命周期约定为“network-pilot 存续期间保留，试点结束删除”。

步骤：先在虚构代理控制台登记目标主机名 `vendor-api.example.invalid`；再为 demo 服务设置 `HTTPS_PROXY=http://demo-egress-proxy-01.demo.example.invalid:8443`；然后在服务的 demo 测试容器内执行 `curl -fsS https://vendor-api.example.invalid/health`。验证标准是响应文本为 `demo-ok`，且代理观测页出现目标主机名和成功结果。

若验证失败，立即移除该服务的 `HTTPS_PROXY` 配置，并从虚构代理控制台撤销目标登记。常见问答：黄区服务能否照做？不能，黄区在该虚构模型中不允许外联，应先走架构决策流程，而不是套用本演练。
